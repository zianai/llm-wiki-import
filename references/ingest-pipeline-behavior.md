# Ingest pipeline behavior: how drafts become wiki/sources

Historical corpus observations below include app v0.1.x. Controlled evaluations on 2026-09-20/21 used LLM Wiki 0.6.11 with deepseek-v4-flash; their corrections and limits take precedence over earlier causal interpretations. Consult when choosing input preparation or investigating output quality, not as a guarantee of another version's behavior.

## Required metadata and observed maintenance

- Required source-summary frontmatter: `type: source`, `title`, `created`, `updated`, `tags`, `related`, `sources`. Optional when supplied: `authors`, `year`, `url`, `venue`. These are output requirements, not proof that a particular write succeeded.
- Generated `related` links connect entity/concept pages; the pipeline also maintains `wiki/log.md` and `wiki/index.md`. Verify actual artifacts with `llm-wiki-import`; metadata or aggregate-page writes alone do not prove source-summary generation.
- `.llm-wiki/` holds application state, not the project's editable schema/purpose inputs. The user-editable `schema.md` and `purpose.md` in the project root inform both stage prompts. Their primary role is page types, routing and project purpose; they are not a hardcoded source-summary body template.

## Narrative layer (soft, LLM-written)

- Common section patterns observed in this corpus include 来源概况/来源信息, 核心主张/核心论点/核心结论, 证据强度评估/事实核查/编者核查注, and 编者注/待解问题/关联阅读. These are corpus observations, not mandatory application slots.
- Output depth varied with input and corpus: early thin inputs produced short stubs, while the later short-input experiment produced a much longer page with limited factual evidence. Length and structure do not establish factual completeness.
- Draft organization can influence the summary: historical runs retained quote blocks, image transcripts and fact-check tables. It is not the sole prompt or a guaranteed output skeleton; application prompts, stage-1 analysis, schema/purpose, model priors and available corpus can also shape the result. Empty-project controls generated evaluation sections and query pages from minimal inputs.
- Possible style self-reinforcement: entries imported without editorial discipline grew 核查/证据强度 sections in a corpus dominated by those patterns. This is consistent with a corpus influence; these observations alone do not isolate its causal contribution.
- Incremental rewrites: a new source can trigger updates to existing concept/entity pages; `page-history/` snapshots keep previous versions.

## Practical consequences

- Extraction supplies original material and provenance; composition keeps verbatim text separate from link mappings, image transcripts, fact-check results and editor notes.
- The application can generate evaluation and questions in an empty project; mature corpus and four-part composition are not necessary conditions. These structures cannot substitute for acquired evidence and can contain incorrect criticism. The controlled runs did not isolate the contributions of stage-1 analysis, schema and model priors.
- Delivery success and content quality are separate. `llm-wiki-import` verifies processing; `wiki-output-review` checks needed facts, attribution, reasoning and links in the actual pages. It distinguishes evidence never supplied in the draft from information lost or misinterpreted during generation.
- Fix drafts before ingest when possible. For existing entries, `wiki-draft-composition` prepares the revision and identifies affected material; `llm-wiki-import` delivers and verifies the ready revision. Cleanup of stale raw/wiki material and derived narratives is a separate knowledge-base maintenance task; deleting raw alone or importing a revision does not establish that cleanup is complete.
- Improved output was observed while the displayed app version remained 0.1.x. The unchanged version label alone does not rule out application changes or establish what caused the improvement.

## Source mechanisms and version scope

Historical inspection covered `src/lib/ingest.ts` and `src/lib/templates.ts` of nashsu/llm_wiki. The stage-1 handoff correction below is verified against [ingest.ts at e808211](https://github.com/nashsu/llm_wiki/blob/e8082119649e6a8e1cf85eaf289adcabfdf39d4e/src/lib/ingest.ts#L1077), also used by the 0.6.11 evaluation; do not assume unchanged implementation in other versions.

- The generation prompt does not prescribe a fixed set of source-summary body headings. It constrains source identity/path, frontmatter, FILE blocks and content rules. Body organization may reflect the draft, stage-1 analysis, application instructions, schema/purpose, model priors and corpus; exact source-path mapping is version-specific (see api-reference.md).
- Stage-1 analysis uses structured headings and asks for evidence assessment, contradictions and open questions. Its output is passed directly to stage-2 generation as context, with an instruction not to echo the analysis. Fallback is an additional path when the generated summary is missing; the earlier “via fallback only” interpretation is withdrawn for this revision. See [analysis prompt](https://github.com/nashsu/llm_wiki/blob/e8082119649e6a8e1cf85eaf289adcabfdf39d4e/src/lib/ingest.ts#L2191).
- Fallback (`buildFallbackSourceSummary`): if the LLM omits the summary page, the app attempts to write frontmatter + title + the ENTIRE stage-1 analysis verbatim (deliberately untruncated). A successfully written fallback carries that analysis; the fallback mechanism itself does not prove the file was written.
- Images: `injectImagesIntoSourceSummary` appends a marker-bracketed `## Embedded Images` section (idempotent, captions as alt for search); if the page is missing entirely it writes a minimal stub first.
- log.md: written deterministically by code when the LLM omits its FILE block (no extra LLM turn).
- Five scenario templates (research/reading/personal-growth/business/general) seed `schema.md`/`purpose.md` at project creation; editing them afterwards is the supported way to change routing.
- Filename rule in code = original raw filename minus extension; the templates' `author-year-slug.md` advice is only advisory schema text (real corpus uses original clip filenames).

## Historical A/B observations (retain outputs, not unsupported causal claims)

- A/B test (2026-09, EP-Harness article, same app/model, successive ingests 1 min apart): native-clip draft → source page mirrors the ARTICLE's section skeleton (14 files, strong entities, 2 critical query pages, independent critiques like attribution ambiguity); four-part draft → page mirrors the DRAFT's skeleton (8 files, verbatim anchor + fact-check + cross-source tensions + open questions). These outputs support an influence of draft structure. Even the unprocessed input produced an evidence-strength section and critical queries in the style-matured corpus; this experiment did not isolate the corpus effect. The composed draft supplied a verbatim anchor, pre-import fact-checks, cross-source tension notes and claim attribution. External evidence missing from both the input and existing corpus cannot be reliably reconstructed by ingest alone. Later ingest also reused earlier ingest's fresh concept/query pages, so the runs did not have identical corpus states.
- A/B test 2 (2026-09, X hype tweet, 179-char candidate text): native clip → an evidence table marking claims "weak", open questions without supporting facts, unexpanded t.co links, unknown license and publish date wrongly set to clip date. Four-part draft → expanded links, GitHub license check, image OCR of human-in-the-loop buttons and timeline reconstruction. Run B also reused run A's fresh 逆向开源 concept and query pages. These are historical output observations, not a controlled estimate of composition benefit.
  - Correction (2026-09-20): the later local extraction record reports 179 characters from syndication with range [0,179], but a 514-character candidate from FxTwitter for the same tweet. This review did not independently fetch or verify those texts. The former claim that the API candidate was safe as complete original text is withdrawn; response-field self-consistency is not completeness evidence, and a longer candidate is not itself verified full text.
  - The experiment therefore has a possible extraction-truncation confound: it cannot establish that the original source was naturally thin, that the output gap was caused solely by composition, or that composition benefit scales with source poverty. Which facts added to B may already have been present in omitted original text remains unchecked. Retain the recorded outputs, but an A/B comparison using verified complete original text has not been established by this experiment.

## Controlled evaluations: current decision guidance (2026-09-20/21)

- **Long-form/web evaluation:** two sources, four input routes, one run per cell in empty projects. Native HTML could generate critical structure and preserve core content; noisy HTML, lost link/code boundaries and missing chart relationships created other risks. The official clipper-code fallback was a static reproduction, not an end-to-end installed-extension test. [Report and evidence](/Users/a/Documents/Obsidian/llm-wiki-evaluations/controlled-20260920/evaluation.md).
- **X evaluation:** two performance-promotion sources × four input arms × two planned repetitions, 16 isolated empty projects. A was prepared complete minimal text, B added metadata/link mappings/image transcription, C added sourced checks, D rearranged C's identical blocks into four sections. All used native Markdown file import, with image captioning off and media URLs rather than image attachments. It did not compare actual native X capture with skill extraction. [Report and frozen evidence](/Users/a/Documents/Obsidian/llm-wiki-evaluations/x-controlled-20260921/evaluation.md).
- The X source/whole-wiki coverage scores (each /20; R1/R2) were P1 A 7/6, B 13/13, C 16/17, D 17/17; P2 A 6/6, B 15/15, C 20/20, D 20/20. A→B gained 6–9 points and B→C gained 3–5; C→D differences were +1, 0, 0, 0. This supports information acquisition and targeted checks in these cases, not a stable independent four-section advantage or strict equivalence. Four sections remain optional for human review and provenance boundaries.
- C/D retained checked facts in wiki, but P1 drafts omitted available benchmark conditions and a reproduction pointer. That shared coverage gap was mainly an input-selection omission. A separate C output reversed the meaning of a GPU reduction despite correct supplied counts. Diagnose the point where information was absent or altered; do not assign all missing facts to ingest.
- Empty A inputs produced evidence evaluation and query pages. Some outputs invented wrong arithmetic, dates or criticism, and high-coverage outputs still had attribution errors and broken links. Coverage, unsupported claims, confirmed errors and link quality require separate reporting; a cache receipt proves none of them.
- Limits: two materials are not sixteen independent samples; reviewers were mapping-hidden, not fully blind. The X report discloses a voided initial review and re-anonymized fresh review. No source-available/noncommercial-license challenge or extreme 179-character case was tested. Neither evaluation established end-to-end speed or cost advantage; preparation costs were not allocated by arm. Do not merge the two experiments' different scoring scales or turn them into universal native-versus-skill rankings.
